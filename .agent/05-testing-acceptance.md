# 分册 5｜测试与验收规范

> 归属总纲：`../1-总纲/AGENT.md`
> 当前口径（**开发初期**）：**能构建、能启动、接口能调通、页面不报错**即算通过；不强制多轮循环。
> 待功能稳定/进入联调或上线前，再按 §6 升级为完整回归（届时以升级版为准）。

---

## 1. 最小验收模型（一轮四步）

| 步骤 | 名称 | 目标 | 通过标准 | 失败动作 |
|------|------|------|----------|----------|
| 第 1 步 | 构建 | 代码能编译 | `go build ./...` 无 error（仅 warning 可接受） | 修编译错误，重跑 |
| 第 2 步 | 启动 | 服务能起来 | 进程正常启动、日志无 panic、端口可访问 | 修启动问题，重跑 |
| 第 3 步 | 接口 | 新接口能调通 | Apipost 正常用例返回 `code=0`，数据落库正确 | 修接口，回到第 1 步 |
| 第 4 步 | 页面 | 页面能打开可用 | 页面不白屏、Console 无 Error、主流程点得通 | 修页面，回到第 1 步 |

**要求**：四步都跑过一遍即可交付，**不要求 3 次完整循环**；自己发现的问题修完把对应步骤重跑一次就行。

---

## 2. 第 1 步：构建（必须通过）

```bash
go build ./...      # 全量编译，必须无 error
go vet ./...        # 静态检查，报错必修；风格类提示可暂缓
```

说明（开发初期放宽项）：
- `gofmt`/`goimports` 风格差异**不作为阻塞项**，但新增文件请保持与相邻文件一致。
- 仓库既有历史报错（非本次改动引入，例如 `plugin/announcement/gen`）不要求本次修复，但**不得新增报错**。
- `swag init` 建议在新接口写完后执行一次；`docs/` 未更新可在 PR 说明里注明"后续补"，不算阻塞。

---

## 3. 第 2 步：启动（能跑起来）

- [ ] `go run main.go`（或已构建的二进制）能正常启动，无 panic、无端口占用冲突。
- [ ] 启动日志能正常连接 `global.GVA_DB`（gva 库）、`global.LUOBO_DB`（luobo 业务库）、`global.GVA_REDIS`；缺配置时有明确告警而不是静默失败。
- [ ] 浏览器/curl 能访问到健康检查或任一已有接口。

---

## 4. 第 3 步：接口自测（Apipost，最小用例）

**每个新增/变更接口至少跑 2 个用例**：

| 类别 | 示例 | 期望 |
|------|------|------|
| 正常 | 必填齐全、合法值 | `code=0`，`data` 正确，写接口已落库 |
| 失败 | 缺必填 / ID 不存在 | 返回失败 code 与中文提示，不 panic、不返回 500 堆栈 |

要点：
- 写接口确认落库结果（`created_by`、`deleted_at`、`ticket_no`/`session_no` 等单号已生成）。
- 列表接口确认能返回数据、分页字段（`total`、`page`、`pageSize`）正确。
- 边界/越权等用例开发初期**可选**，记入待办后续补。

---

## 5. 第 4 步：页面自测（浏览器不报错即可）

1. 打开发对应页面，**F12 Console 无 Error**（warning 可接受）。
2. 主流程点一遍：列表加载 → 新增（或编辑）→ 保存成功 → 列表刷新看到数据。
3. 页面能正常展示空态/加载态，不白屏、不卡死。
4. 接口 4xx/5xx 时有提示，不是空白页。

---

## 6. 后续加严（功能稳定 / 联调 / 上线前）

满足以下任一条件时，测试回到完整口径：

- 进入前后端联调、提测、上线前；
- 涉及资金、权限、数据删除、批量导入等高风险改动；
- 线上出现过缺陷的模块再次改动。

完整口径要求（届时执行）：
1. 本地：`go build` / `go vet` / 单测 / swagger 全绿。
2. 接口：正常、边界、异常、权限四类用例全覆盖，结果有记录。
3. 页面：功能闭环 + 空态/失败态/无权限态 + 双分辨率截图。
4. 回归：同模块及关联模块核心链路重跑一遍。
5. 缺陷全部闭环（有复现、有修复 commit）。

---

## 7. 通过标准（开发初期 DoD）

- [ ] `go build ./...` 无 error，且本次改动未新增 vet 报错
- [ ] 服务能启动，日志无 panic
- [ ] 新增/变更接口 Apipost 正常用例调通，数据落库正确
- [ ] 页面能打开，Console 无 Error，主流程点得通
- [ ] 已知遗留问题（含放宽项）在 PR 描述里列明，不隐瞒

---

## 8. 不可放宽的红线

1. 禁止明显编译不过、启动 panic 的代码提交。
2. 禁止在测试/开发库执行无 WHERE 的 `UPDATE/DELETE`，禁止跑生产 DDL。
3. 禁止用生产数据调试；测试数据需脱敏。
4. 禁止日志打印密码、token、手机号等敏感信息。
5. 禁止"没跑过就宣称验证通过"——至少自己按 §7 走一遍并说明结果。
